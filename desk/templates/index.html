TRANSPARENCY / WHAT WE CHECK

Every finding
has a source.

The workbench matches submitted package versions against OSV evidence. It does not install packages, run exploits, or certify a release.

01

Offline by default

Four exact-version OSV responses are bundled for the demo. Other versions stay unverified until a live query completes. Each package displays its own retrieval time.

OSV data sources ↗
02

Opt-in live checks

A live scan sends only normalised PyPI names and versions to api.osv.dev. Your manifest text and scan name stay local. Timeouts and partial results are visible, never translated into a clean result.

OSV API documentation ↗
03

Deliberate scope

One exact package==version pin per line; up to 30 packages. Ranges, extras, environment markers, nested files, URL dependencies and local builds are flagged rather than resolved.

No transitive dependency analysis or runtime reachability analysis.

04

Readable evidence

Records sharing a CVE or GHSA identity are grouped. Upstream severity and fixed-version markers are shown as source metadata; compatibility still needs a separate review.
